# 学习路线图

这份文档回答一个问题：**16 个练习站，按什么顺序练，每一站到底在补哪块能力。**

---

## 一、先把能力分层

游戏开发的能力不是一个平面，它有明显的依赖关系。层次搞反了，会一直在"能跑但很怪"的状态里打转。

```
第 4 层  工程能力      存档、音频、对象池、程序化生成、性能
         ↑ 让游戏"做得完、跑得动、发得出去"
第 3 层  系统能力      战斗、AI、数据驱动、背包、状态效果、事件总线
         ↑ 让游戏"有内容、可扩展"
第 2 层  手感能力      输入缓冲、相机、打击感、UI 反馈
         ↑ 让游戏"好玩"
第 1 层  地基          场景树、生命周期、信号、物理与碰撞、状态机
         ↑ 让游戏"能动、不崩"
```

**第 1 层不牢，后面全是玄学。** 比如：
- 分不清 `_Process` 和 `_PhysicsProcess`，就会做出"帧率越高跑得越快"的角色；
- 不懂碰撞层与掩码，就会永远在问"为什么我的子弹打不到敌人"；
- 不会用信号，就会写出一个改动一处、十处报错的脚本网。

## 二、推荐顺序

### 第一波：地基（S01 → S02 → S03 → S04）

目标：能独立做出一个"操作跟手、碰撞正确、状态清晰"的角色。

| 站 | 你会掌握 |
|---|---|
| S01 节点与生命周期 | 场景树结构、`_EnterTree/_Ready/_Process/_PhysicsProcess/_ExitTree` 的确切时机、信号、分组 |
| S02 输入与手感 | InputMap、轮询 vs 事件、**输入缓冲**、**土狼时间**、可变跳跃高度、冲刺 |
| S03 物理与碰撞 | 层与掩码（最容易搞错的地方）、`CharacterBody2D.MoveAndSlide`、`Area2D` 检测、`RayCast2D` |
| S04 状态机 | 把 if-else 泥潭换成显式状态与转移条件 |

> 这一波结束后，回头看你以前写的移动代码，会有明显的"当时我在瞎写"的感觉。

### 第二波：手感（S05 → S06 → S16）

目标：同样的机制，做得比别人"爽"。

| 站 | 你会掌握 |
|---|---|
| S05 相机与打击感 | 相机跟随与边界、**屏幕震动**、**顿帧（hitstop）**、前瞻 |
| S06 UI 与 HUD | `Control` 与容器布局、锚点、`Theme`、分辨率适配、暂停菜单与焦点导航 |
| S16 状态效果 | Buff/Debuff 的叠加与刷新规则、冷却、用 `Tween` 做 UI |

### 第三波：系统（S07 → S08 → S09 → S10）

目标：让游戏有内容，而且加内容不用改核心代码。

| 站 | 你会掌握 |
|---|---|
| S07 战斗与数值管线 | Hitbox/Hurtbox 分离、伤害计算顺序、无敌帧、击退、伤害飘字 |
| S08 敌人 AI 与寻路 | 视野锥、听觉、`NavigationAgent2D` 绕路、群体分离 |
| S09 数据驱动 | 自定义 `Resource` + `.tres`，把数值从代码里搬出去 |
| S10 背包与物品 | **数据模型与视图分离**、拖拽、堆叠、装备槽 |

### 第四波：工程（S11 → S12 → S13 → S14 → S15）

目标：把"能玩的原型"变成"做得完、跑得动、发得出去"的项目。

| 站 | 你会掌握 |
|---|---|
| S11 存档与读档 | 序列化、存档槽、**版本迁移**、损坏存档处理 |
| S12 音频 | 音频总线、SFX 复用池、音乐交叉淡入、随机音高 |
| S13 事件总线 | Autoload、全局信号、解耦的收益与代价、连接泄漏 |
| S14 对象池与性能 | 对象池、`MultiMesh` 批绘制、看性能分析器找瓶颈 |
| S15 程序化生成 | 种子随机、`FastNoiseLite`、房间生成与连通性、`TileMapLayer` |

## 三、每一站的固定练法

四个动作，缺一不可：

1. **玩**（3 分钟）：进去把这一站玩明白，先建立直觉。
2. **读**（10 分钟）：看这一站的代码与文档，搞清楚"为什么这样写"。
3. **改**（30~60 分钟）：按站内 `TAB` 面板里的 5 条任务逐条改。**每改一条就重跑一次**，
   看清楚现象的变化，而不是只看有没有报错。
4. **重写**（1~2 小时）：关掉参考实现，把这一站的核心机制自己从零写一遍。
   写不出来，说明第 3 步只是在抄，不是在学。

> 判断自己真的学会了的标准：**能不能不看原代码，把这一站讲给别人听，并说出每个设计选择的理由。**

---

## 四、贯穿全程的四个习惯

1. **先测量再优化**：`F3` 打开性能面板，改代码之前先记下当前的 FPS / 帧时间 / 绘制调用数。
2. **小步提交**：每完成一条练习任务就 commit 一次。这样"改坏了"最多损失一条任务。
3. **一次只改一个变量**：同时改三个地方然后出 bug，等于没做实验。
4. **让错误早点暴露**：能用 `PushError` / 断言查出来的问题，不要留到运行时靠肉眼发现。

练完对应站点后，问自己这些问题。答不上来就回去重练。

- [ ] 碰撞层（layer）和掩码（mask）分别是什么意思？【S03】
- [ ] 为什么位移要写在 `_PhysicsProcess` 里？【S02/S03】
- [ ] 跳跃缓冲和土狼时间各解决什么问题？不加会怎样？【S02】
