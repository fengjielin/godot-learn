# S07 · 战斗与数值管线

> **练什么**：Hitbox/Hurtbox · 伤害计算顺序 · 护盾 · 暴击 · 无敌帧 · 击退 · 飘字对象池
> **一句话**：战斗是一整条**有顺序的管线**，不是"碰到就减血"。
> **难度**：★★★☆☆（每一环都简单，难的是**顺序**和**可观测**）

---

## 一、先玩一遍

走到假人旁边按 `J` 砍它。**真正的内容在左上角那块面板上** ——
它把最近一次命中的每一环都摊开：

```
【伤害管线】最近一次命中：
   ▶ ① 命中判定   Hitbox ∩ Hurtbox —— 命中（基础伤害 12）
   · ② 无敌帧     不在无敌中，继续结算
   ▶ ③ 暴击判定   15% 命中 → ×2 → 24
   ▶ ④ 护盾吸收   护盾 30 → 6（吸收 24），剩余伤害 0
   · ⑤ 生命扣减   HP 100 → 100（−0）
   ▶ ⑥ 击退       力度 200，方向 (0.99, 0.14)
   · ⑦ 进入无敌帧 接下来 0.50s 内免疫一切伤害
```

按 `1`~`5` 随时把某一环关掉（护盾 / 暴击 / 无敌帧 / 击退 / 飘字池），
再砍一刀，**看面板上少了哪一行、少了多少伤害**。这比读代码快十倍。

## 二、核心概念一：顺序就是设计

管线顺序不是"写到哪算哪"，每一个位置都对应一个具体的设计意图：

| 顺序 | 放在这里的原因 |
|---|---|
| ① **无敌帧检查在最前** | 被免疫的一击应该**完全没发生过**：不消耗护盾、不触发暴击、不产生击退。放在后面就会出现"无敌期间敌人还在掉护盾"这种诡异现象 |
| ② **暴击在护盾之前** | 暴击是"这一击有多重"（攻击属性），护盾是"承受了多少"（防御属性）。**先算攻击，再算防御** |
| ③ **护盾先于生命** | 玩家最熟悉的规则：盾不够就溢出到血 |
| ④ **击退方向 = 攻击者 → 受击者** | 不是"受击者当前朝向的反方向"。前者在玩家绕后攻击时依然正确，后者会把人往奇怪的方向推 |
| ⑤ **进入无敌帧在最后** | 它保护的是"接下来"的伤害，不是这一次 |

> **这条顺序不是唯一正确的，但它必须是一个明确的决定。**
> 绝大多数战斗 bug 都出在顺序上 —— 而且表现出来往往是"数值不对"，
> 让你去查公式，其实是顺序错了。

## 三、核心概念二：为什么要把"过程"也留下来

```csharp
public sealed class DamageResult
{
    public int BaseDamage, ShieldAbsorbed, HpLost, ...;
    public bool WasCrit, BlockedByIFrame;
    public List<DamageStep> Steps { get; }   // ← 每一环的输入输出
}
```

只留下最终数字的话，遇到"为什么这次是 24 那次是 12"你只能靠猜。
把每一环都记下来，面板一显示，答案就在眼前。

**这和 S04 状态机那块面板是同一个思路：能观测，才能调。**
代价是每次命中多分配一个 `DamageResult` —— 对这个规模的游戏完全可以接受，
真的到了性能瓶颈（S14）再优化。

## 四、核心概念三：飘字对象池

本站把池的收益**直接量化出来**：

```
【飘字池】创建 3 个实例，走池 47 次，省下 44 次 Instantiate（峰值同时 3 条）
```

一次连击可能瞬间产生十几条飘字。每次都 `Instantiate` + `QueueFree` 的代价是：
频繁的内存分配（GC 压力）、节点树的反复增删、以及**恰好在打得最爽的时候卡一下**。

**池化对象有两条铁律**：

1. **`Play()` 里必须把所有会残留的东西全部重置。**
   位置、颜色、字号、缩放、透明度、计时器 —— 漏掉任何一个，
   下一次复用时它就会带着上一次的痕迹出现。这种 bug 看起来像"随机发生"，
   其实是你漏了一个字段。
2. **池化对象不能自己 `QueueFree`。** 它只能把自己标记为空闲，
   **销毁权必须只有一方持有**。本站的 `DamageNumber` 为此专门有个
   `AutoFreeOnRelease` 开关，只有"不在池里"的对照实验才打开它。

按 `5` 关掉池，再砍几刀 —— 面板上"创建"那个数字会开始一路涨，
而"省下"停在原地。**这就是池化到底省了什么。**

## 五、核心概念四：Hitbox 与 Hurtbox

| | 谁持有 | 碰撞层/掩码 | monitoring / monitorable |
|---|---|---|---|
| **Hitbox**（攻击框） | 攻击方 | layer=`PlayerAttack`, mask=`Enemy` | `true` / `false` |
| **Hurtbox**（受击框） | 受击方 | layer=`Enemy`, mask=`0` | `false` / `true` |

分开的好处：
- **一把武器换判定形状不用碰角色**；
- **一个角色能被多种东西打，只需要一个受击框**；
- 两者是**独立的对象**，所以"这次挥砍对同一目标只结算一次"这种规则
  有地方放（见 `MeleeSwing._hitTargets`）。

本站的 `MeleeSwing` 做成一个**只存在 0.12 秒的独立对象**，而不是让玩家每帧检测。
因为"挥砍"是一个**有始有终的动作**：做成对象之后，前摇/判定/后摇天然分离，
每把武器可以有自己的形状和参数。写在玩家身上，这三件事都会变成"靠标志位硬凑"。

## 七、五条练习任务的提示

### ① 让伤害先扣护盾、再扣血，并显示护盾条
**难度**：★★
已经做了。练习：

1. 按 `1` 关掉护盾，砍一刀 —— 面板上 ④ 那一行变成"护盾已关闭"，
   ⑤ 的生命扣减**立刻变大**。**这就是"改一处、看全局"的感觉。**
2. 把 `MaxShield` 从 30 改成 200，再砍。想想：**护盾比血多的时候，游戏变成了什么？**
   （提示：等于给了一个"必须先破盾"的阶段。这是很多 Boss 战的结构。）
3. 加一个"护盾回复"：脱离战斗 3 秒后每秒回 5 点。
   （提示：这已经是 S16 状态效果的雏形了。）

### ② 加入暴击：15% 概率双倍伤害，飘字变黄
**难度**：★
已经做了。练习：

1. 把 `CritChance` 改成 `1.0f`，看暴击 100% 时的表现。
2. 把 `CritMultiplier` 改成 `3f`，再看。
3. **真正的练习**：让暴击**不吃护盾溢出**。现在的规则是
   "暴击先算总伤害，再让护盾吸收"，所以一个 24 的暴击打 6 点盾，会溢出 18 到血。
   改成"护盾按**基础伤害**吸收，暴击部分直接进血"——
   然后回答：**这两种规则，哪种让"堆护盾"更有价值？为什么？**
   （这是数值策划每天在做的取舍。）

### ③ 受击后 0.5 秒无敌帧，角色闪烁
**难度**：★★
已经做了。练习：

1. 按 `3` 关掉无敌帧，然后**疯狂按 J** —— 伤害会瞬间爆炸。
   **这就是"没有无敌帧"的战斗：多段攻击变成绞肉机。**
2. 把 `InvulnerableSeconds` 改成 `1.5f`，感受另一端（打上去像打在棉花上）。
3. **关键练习**：无敌帧现在写在**受击方**身上。
   如果想做"每个敌人独立计算无敌帧"，这样做对吗？
   如果想做"每次攻击对同一目标的冷却"（防止一个 AOE 打多下），
   这个开关应该放在哪？（提示：放在 `MeleeSwing._hitTargets` 那种地方。）

### ④ 加击退：方向 = 攻击者 → 受击者，力度可调
**难度**：★★
已经做了。练习：

1. **这个练习有真实数据**：本站最初把击退设成 260，
   结果每一击都把假人推出攻击范围，**55 次挥砍只命中 2 次**，演示完全进行不下去。
   改成 200 之后玩家可以边打边跟。
   → 把 `Knockback` 改回 260，自己感受一下"演示为什么做不下去"。
2. 给假人加"击退抗性"（`KnockbackResistance`），让体型大的敌人被推得更少。
3. 想一想：**为什么训练假人要加"弹簧归位"？**
   （提示：不加的话，打几下就把它推到墙角，之后所有挥砍全部打空气。
   **展示型场景里的每个物体，都要问一句"反复使用之后它会漂到哪里去"。**）

### ⑤ 给伤害飘字做对象池，避免每次都 Instantiate
**难度**：★★★
已经做了，并且把收益量化了。练习：

1. 按 `5` 关掉池，砍 20 刀，看面板上"创建"和"省下"两个数字的变化。
2. 把 `DamageNumber._life` 从 0.85 改成 3.0，再砍 ——
   需要的实例数会大幅上升（因为每条飘字占用时间更长）。
   **池的大小由"同时存活数量"决定，不由"总次数"决定。**
3. **真正的挑战**：现在的池是"按需增长、永不收缩"。
   加一个"空闲超过 10 秒就回收一半"的逻辑，并回答：
   **什么情况下回收反而更糟？**（提示：玩家一波一波地打的时候，
   每次回收都会导致下一波重新创建 —— **抖动**比"一直占着"更贵。）

## 八、常见坑速查

| 现象 | 原因 |
|---|---|
| 无敌期间敌人还在掉护盾 | 无敌帧检查放太后面了。它必须在**最前面** |
| 暴击打护盾时数值看起来"亏了" | 暴击和护盾的先后顺序搞反了 |
| 击退方向不对（把人往墙里推） | 用了"受击者朝向的反方向"，应该用"攻击者→受击者" |
| 一次 AOE 对同一目标打了好几段 | 缺少"本次攻击对同一目标只结算一次"的记录 |
| 飘字带着上一次的颜色/字号出现 | `Play()` 里漏了重置某个字段 |
| 池化对象被销毁后池还引用着它 | 池化对象自己调了 `QueueFree`。**销毁权只能有一方** |
| 假人被打到墙角之后演示就废了 | 没有归位机制。反复使用的展示物要考虑"它会漂到哪" |
| 连击时卡顿 | 每次命中都在 Instantiate/Free。用对象池 |

## 九、通关后做什么

1. 打开 `common/combat/Damageable.cs`，把管线的顺序**故意打乱两处**，
   然后玩一会儿，看能造出哪些诡异的 bug。
   **亲手制造一次"顺序错"的 bug，比读十遍这个文档记得住。**
2. 想清楚：**为什么 `Damageable` 是 `Node` 而不是 `Node2D`？**
   （提示：它没有位置。位置在它服务的那个角色身上 ——
   这是一种"组件"思路。它带来的好处是：任何东西都能挂它，
   哪怕那个东西不是 2D 物体，比如一个游戏状态或一段剧情。）
3. 给敌人加"受击硬直"：被打中时短暂无法行动。
   这需要 S04 的状态机 —— 去把 `Guard` 拿过来接到这套伤害管线上。
   **做完你会意识到：状态机和战斗系统是两套东西，但它们必须能拼起来。**
4. 去 `docs/00-学习路线图.md` 看一眼自检清单里 S07 那条，确认你能答上来。
