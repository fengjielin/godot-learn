# S16 · 状态效果

> **练什么**：Buff/Debuff · 叠加与刷新 · 冷却 · 免疫 · 持续伤害 · Tween 倒计时环
> **一句话**：**同名效果再次施加时该怎么办？** —— 这一个问题就是整个状态效果系统的核心。
> **难度**：★★★☆☆（不难写，但每一个决定都会变成手感）

---

## 一、先玩一遍

地上四个药水台：**加速 / 中毒 / 无敌 / 回血**。**站上去就会持续施加**，
于是你立刻会撞上那个核心问题。

面板会把**每一次施加**的判定过程摊开（和 S07 的伤害管线是同一套思路）：

```
【最近一次施加】中毒
   · ① 免疫检查   未被免疫，继续
   · ② 冷却检查   不在冷却中，继续
   ▶ ③ 叠加规则   最多 5 层，原有 4 层 → 叠到 5 层（新层独立计时）
   结果：中毒 5 层，最长剩余 5.00s
```

图标下面有**倒计时环**，是用 Tween 驱动的。

## 二、核心概念一：三种叠加规则

| 规则 | 用在哪 | 连踩两次会怎样 |
|---|---|---|
| **Refresh**（刷新时长） | 加速、无敌、回血 | 不会更强，只是倒计时重置为满 |
| **Stack**（叠层） | 中毒、流血、点燃 | 多一层，**每层独立计时** |
| **Ignore**（已有则无效） | 变身、霸体 | 明确拒绝，而不是悄悄吞掉 |

**选错了会做出很怪的手感**：
- 把加速做成 Stack → 连踩五次跑得飞起，玩家会去找这个 bug 用；
- 把中毒做成 Refresh → 叠层玩法整个消失，"连击"失去意义。

### ★ 叠层和刷新最本质的区别

**每层独立计时。**

中毒叠到 3 层时，三层各有自己的倒计时。第一个到期的消失、剩下两层继续。
如果做成"共享一个倒计时"，那么每叠一层就等于刷新全部 —— 那是 Refresh，不是 Stack。

### 一个必须明确决定的细节：层数满了怎么办

本站的规则是**移除最早的一层、补上新层**。另外两种常见做法是：

- **直接拒绝** —— 层数满了就不再受理（简单，但玩家会觉得"我打上去没反应"）
- **刷新全部层** —— 强度不变但时间拉满（会让叠层变成"只要一直在打就永远不掉"）

**三者手感完全不同.** 没有一个"正确答案"，但**必须是一个明确的决定** ——
而不是"代码写到哪算哪"。

## 三、核心概念二：冷却和持续时间是两件事

| | 含义 |
|---|---|
| **持续时间** | 效果在身上挂多久 |
| **冷却** | 多久之内**不能再次施加** |

没有冷却的话，站在药水台上就能无限刷新 —— 前两条规则全都没意义了。

**而且冷却是要调的。** 本站的中毒冷却最初设 `0.35s`，
比药水台的 `0.22s` 重试间隔还长，实测站在毒池里 5 秒只叠到 **3 层**。
调到 `0.20s` 之后 1 秒多就能叠满。

> **冷却必须短于"玩家愿意待在那里的时间"**，否则叠层会显得迟钝。

## 四、核心概念三：免疫

```csharp
if (def.Id == Poison && IsInvulnerable)
{
    result.Add("① 免疫检查", "当前处于【无敌】—— 中毒被完全免疫", applied: false);
    return result;   // 注意：直接返回，不消耗冷却、不叠层
}
```

两条要注意的：

1. **无敌必须也免疫中毒**，否则"无敌"就不成立了。
   这条规则写在**容器的施加逻辑里**（"有毒要进来时，先问一句我是不是无敌"），
   因为它描述的是"谁能进来"，属于容器的职责 —— 而不是中毒自己的属性。
2. **被免疫的一击应该"完全没发生过"**：不消耗冷却、不叠层、不触发任何后续。
   这和 S07 里"无敌帧检查放在管线最前面"是同一条原则。

## 五、核心概念四：用 Tween 驱动倒计时环

倒计时环是一条 `Line2D` 画的圆弧，点数由进度决定。驱动它的是：

```csharp
tween = CreateTween();
tween.TweenMethod(Callable.From<float>(t => SetRing(id, t)), 0f, 1f, def.Duration);
```

`TweenMethod` 补间的**不是一个属性，而是一次函数调用**。
这在"我要动画化的东西不是节点属性"时特别有用 —— 圆弧的进度、shader 参数、
外部系统的数值，都能这么驱动。

**每次成功施加都 `Kill()` 旧的 tween 再建一个新的** —— 这样刷新/叠层时环会从头开始。
（如果不 Kill，旧的 tween 还在跑，环会闪。）

## 七、五条练习任务的提示

### ① 加「冷却」：同一个 buff 在冷却期内不能重复施加
**难度**：★★ 已经做了。练习：

1. 把中毒的冷却改回 `0.35f`（或更大），站到毒池里 —— **你会看到层数涨得很慢**。
   这条我实测过：0.35s 时 5 秒只叠到 3 层。
2. 想一想：**冷却应该是每个效果各自一个，还是全局共用一个？**
   两种设计各适合什么游戏？
3. 给加速加一个"冷却比持续时间还长"的设定（比如持续 3s、冷却 6s），
   然后回答：**这个设计让玩家怎么玩？**（提示：变成了"什么时候用"的资源管理。）

### ② 实现叠层：中毒最多 5 层，每层独立计时
**难度**：★★★ 已经做了。练习：

1. 把 `MaxStacks` 改成 `1`，再站到毒池里 —— 它就变成了"刷新时长"。
   **同一个系统，一个数字的差别就是两种玩法。**
2. 把 `StackRule.Stack` 换成 `Refresh`，看效果有什么不同。
3. **真正的挑战**：给每层加一个"独立受伤间隔"（比如每层各自每 0.5 秒跳一次，
   而不是所有层共用一个计时器）。实现完之后回答：
   **这两种做法在"刚叠上第 5 层的那一瞬间"表现有什么不同？**
   （提示：共用一个计时器时，第 5 层的伤害要等下一个 tick 才出现。）

### ③ 定义叠加规则：同名 buff 是刷新时长还是叠加强度？
**难度**：★★★ 已经做了。练习：

1. 给"回血"加一个第三种玩法：**叠层但强度递减**
   （第 1 层 4 点/秒，第 2 层只加 2 点/秒，第 3 层加 1 点/秒）。
   这是很多游戏控制"堆叠收益"的手段。
2. 加一条"**不同效果之间的互斥**"：比如"无敌期间不能回血"。
   然后回答：这条规则该写在哪？（提示：和"免疫中毒"一样，写在容器的施加逻辑里。）
3. 想一想：如果游戏里有 30 种效果、彼此还有互斥和联动关系，
   靠写在 `Apply` 里的 if 还撑得住吗？那时候需要什么？
   （提示：**效果标签 + 规则表**。这是"数据驱动"在系统层的终极形态。）

### ④ 用 Tween 做图标上的倒计时环
**难度**：★★ 已经做了。练习：

1. 把 `TweenMethod` 换成每帧重算圆弧（在 `_Process` 里按 `remaining / duration` 算）。
   两种做法都跑一遍，**回答：哪种更省？哪种更灵活？**
   （提示：Tween 是引擎帮你插值，省掉了你管计时；但"暂停游戏时它要不要停"、
   "刷新时怎么接上"这些事就得你自己想。本站选 Tween 是因为它天然处理了这些。）
2. 加一个"叠层数"的数字显示在环中间（本站现在只显示在标签上）。
3. 挑战：用 `Tween.TweenProperty` 让图标在效果即将结束时**闪烁**。

### ⑤ 加「免疫」：无敌期间免疫中毒
**难度**：★★ 已经做了。练习：

1. 先踩无敌、再踩中毒 —— 面板会显示"被免疫挡下"。
2. **回答：这条规则的检查放在哪里？** 为什么不是放在"中毒效果自己"里？
   （提示：中毒不知道无敌的存在，也不该知道。**规则属于容器，不属于效果。**）
3. 加一种"**免疫但不清除已有层数**"的语义：无敌期间已经中的毒**暂停计时**
   而不是消失。实现它，然后回答：**哪种更符合玩家直觉？**

## 八、常见坑速查

| 现象 | 原因 |
|---|---|
| 站在药水台上就能无限刷 | 没做冷却。前两条规则全都没意义了 |
| 叠层叠不上去 | 冷却比"玩家愿意待的时间"还长。本站实测 0.35s → 5 秒只叠 3 层 |
| 叠层和刷新分不清 | 实现上共享了一个倒计时。**每层必须独立计时** |
| 无敌期间还能中毒 | 免疫检查漏了，或者写在了错误的地方 |
| 被免疫的一击还消耗了冷却 | 免疫检查必须在**最前面**，且直接 `return` |
| 倒计时环闪烁 | 刷新时没 `Kill()` 旧的 tween，两个 tween 同时在跑 |
| 层数满了不知道怎么办 | 必须明确决定：刷新最早层 / 直接拒绝 / 刷新全部层 |
| 效果过期了但图标还在 | 图标显隐没跟着状态走（本站每帧从 `Find()` 拿真实状态） |

## 九、通关后做什么

1. **把中毒的 `MaxStacks` 改成 1，再玩一遍。** 你会发现"毒池"从一个
   "要赶紧离开的地方"变成了"可以硬扛的地方"。**一个数字改变了整个关卡设计。**
2. 想清楚：**为什么 `StatusEffects` 是挂在玩家身上的一个节点，而不是玩家自己的字段？**
   （提示：敌人也要中毒。**做成组件，才能复用到任何东西上** ——
   这和 S07 的 `Damageable` 是同一个决定。）
3. 打开 `common/effects/StatusEffectDef.cs`，把四种效果各加一条
   `[Export]` 之类的配置化改造，让它们也能从 `.tres` 读。
   **做完之后回答：这一步值得吗？**（提示：本站只有 4 种效果，写死在表里挺好；
   30 种就该搬出去了。**"什么时候搬"和"搬到哪"一样重要。**）
4. 四波练习站到此结束。回到 `docs/00-学习路线图.md`，
   把 18 条自检清单从第一条读到第十八条 —— **能全部答上来的话，你已经不是新手了。**
