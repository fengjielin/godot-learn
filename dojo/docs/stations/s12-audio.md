## 二、★ 本站一个音频素材文件都没有

所有声音都是 `common/audio/SoundKit.cs` 在**运行时合成**的：
把一串 `[-1, 1]` 之间的浮点数按 16 位小端写成字节，塞进 `AudioStreamWav.Data`。

```csharp
var scaled = (short)(value * 32000);
data[i * 2]     = (byte)(scaled & 0xFF);
data[i * 2 + 1] = (byte)((scaled >> 8) & 0xFF);
```

**为什么值得亲手写一遍：** 写完之后你会明白 ——
**音效 = 波形 × 包络**，其余所有音频技巧（淡入淡出、混音、滤波、压缩）都建立在这上面。

### 包络比波形重要得多

```csharp
private static float Envelope(float t, float duration, float attack, float decayRate)
{
    if (t < attack) return t / attack;                    // 起音
    return Mathf.Exp(-(t - attack) * decayRate);          // 指数衰减
}
```

本站的**打击音**和**爆炸音用的是同一个噪声波形**，区别只在包络：

| | 衰减速率 | 时长 | 听感 |
|---|---|---|---|
| 打击音 | 42 | 0.14s | "啪" |
| 爆炸音 | 6.5 | 0.75s | "轰" |

> **同一个波形，只改一个数字，就从"打击"变成"爆炸"。**
> 这就是为什么调音效应该先调包络，而不是先去找更好的素材。

### 音高、波形、包络

- **音高**（频率）→ 听起来是什么音
- **波形** → 听起来是乐器（正弦）、电子（方波/锯齿）还是打击（噪声）
- **包络** → 听起来是什么材质

顺带一句真话：**用代码合成的音效做原型很够用，做正式产品通常不够。**
它的最大价值是"在美术还没给你素材之前，让玩法能跑起来、手感能被评估"。

## 三、核心概念一：音频总线

```
Master（总音量）
 ├── Music（背景音乐）
 └── Sfx（音效）
```

```csharp
AudioManager.Instance.SetBusVolumeLinear("Music", 0.5f);   // 不影响音效
```

**为什么要分层而不是给每个播放器设音量：**
调 Music 的时候你不用去改几十个播放器，也不用担心漏掉一个。
**总线是"全局的音量层"** —— 玩家要的就是这个粒度。

总线还带着**效果**（混响、压缩、EQ）和**静音开关**。
`SetBusMuted` 比把音量设成 0 更好：它不改变音量值，所以"取消静音"能回到原来的音量。

## 四、核心概念二：SFX 复用池（任务 ②）

```csharp
private AudioStreamPlayer CreateVoice() { ... }   // 启动时建 12 个

public void PlaySfxStream(AudioStream stream, ...)
{
    var player = _sfxVoices[_nextVoice];
    _nextVoice = (_nextVoice + 1) % _sfxVoices.Count;   // 轮转
    player.Stream = stream;
    player.Play();
}
```

**池子里只有 12 个声道，第 13 次播放会抢占最早的那个。**

### 为什么要池化，而不是每次新建播放器

| | 每次新建 | 复用池 |
|---|---|---|
| 节点数 | 每播一次涨一个 | 恒定 12 |
| 内存 | 每个播放器 + 音频流都占着 | 复用 |
| 爆音 | 几十个音同时响 → 削波 | 最多 12 个 |
| 卡顿 | 在"打得最热闹"的时候创建节点 | 无 |

> **音效是"一次性播放"的重灾区。** 一次连击可能瞬间触发十几个音效，
> 而它们恰恰发生在你最需要帧率稳定的时候。

### ★ 本站最值得亲手做的一件事

**快速连按 `3` 十几次。** 爆炸音长达 0.75 秒，而池子只有 12 个 ——
面板上的「正在发声」会**卡在 12**，那就是池在工作。

抢占策略还有别的选择，各有取舍：

- **抢占最早播放的**（本站）—— 简单，但如果玩家最在意的是"第一个音"，它会先被砍掉
- **抢占最安静的 / 最不重要的** —— 需要给音效分优先级
- **直接丢弃新的** —— 适合"背景氛围音"，不适合打击音（玩家会以为没打中）

> **"满了怎么办"必须是一个明确的决定**，而不是"代码写到哪算哪"。

## 五、核心概念三：交叉淡入需要两个播放器（任务 ③）

```csharp
// AudioManager
private AudioStreamPlayer _music;      // A
private AudioStreamPlayer _musicAlt;   // B

public void CrossfadeMusic(AudioStream stream, float fadeSeconds = 1.2f)
{
    var incoming = 交替取一个;
    var outgoing = 另一个;

    incoming.Stream = stream;
    incoming.VolumeDb = -60f;
    incoming.Play();

    FadePlayer(incoming, 0f, fadeSeconds);      // 渐强
    if (outgoing.Playing) FadePlayer(outgoing, -60f, fadeSeconds);   // 同时渐弱
}
```

> **"同时有两个播放器"是交叉淡入的前提，不是优化。**
> 只有一个播放器的话，换曲时旧曲子会**戛然而止** ——
> 你只能淡入新的，没法让旧的逐渐消失。

**代价**：过渡期间两条音轨同时在解码播放，CPU 和内存都是双份。
所以 `fadeSeconds` 别设太长（1~2 秒足够），也别同时交叉太多首。

## 六、核心概念四：音高随机（任务 ④）

```csharp
player.PitchScale = 1f + (float)GD.RandRange(-0.10, 0.10);
```

实测波动 0.922 ~ 1.022（±10%）。

> **同一个音效连播十次一模一样的话，耳朵立刻会腻。**
> 这是投入产出比最高的一个音频技巧 —— 一行代码，效果立竿见影。

配套的两个技巧：
- **音量随机**（±2 dB）—— 比音高随机更微妙，适合脚步、环境音
- **采样起点随机** —— 对长音效（比如风声）很有效，避免"每次都从头"的机械感

⚠️ 注意：**音高随机也会影响时长**。`PitchScale = 2` 的音效播得快一倍，
所以它是一把双刃剑 —— 对"滴答"这类有节奏的音效，随机音高会破坏节奏感。

## 七、核心概念五：静音与切后台（任务 ⑤）

```csharp
public override void _Notification(int what)
{
    if (what == NotificationApplicationFocusOut)
    {
        AudioManager.Instance.SetBusMuted("Master", true);
        _autoMuted = true;
    }
    else if (what == NotificationApplicationFocusIn)
    {
        if (!_manualMuted) AudioManager.Instance.SetBusMuted("Master", false);
    }
}
```

**注意退出时要恢复。** 只静音不恢复是个 bug，而且玩家会以为是游戏的音频坏了。

`_manualMuted` 这个标志的作用是：**玩家自己按了静音，切回来时不该被自动取消** ——
自动行为不能覆盖玩家的显式选择。

> 这是"尊重玩家"的一个小细节：玩家 Alt+Tab 出去接个电话，
> 游戏在后台继续放音乐是很烦的。

## 八、★ 一个真实的踩坑记录

S12 做完之后，headless 验证开始 FAIL：

```
WARNING: 2 ObjectDB instances were leaked at exit
```

排查过程（值得学一下）：

1. **先怀疑自己的静态缓存。** `SoundKit` 最初用 `static Dictionary<string, AudioStreamWav>`
   缓存合成结果 —— 静态字段的生命周期比引擎还长，这是"泄漏"的经典成因。
   改成不缓存（缓存交给站台的实例字段）→ **警告依旧**。
2. **再怀疑播放器里的流引用。** 给 `AudioManager` 加 `_ExitTree` 主动 `Stop()` + `Stream = null`
   → **警告依旧**。
3. **不猜了，用 `--verbose` 让引擎自己说**：

```
Leaked instance: AudioStreamWAV:9223372069872338622 - Reference count: 1
Leaked instance: AudioStreamPlaybackWAV:9223372069922670273 - Reference count: 1
```

**正好是一个正在播放的音乐流 + 它的播放对象。** 而 `Reference count: 1`
说明还有一方握着它 —— 音频服务器。

4. **结论**：引擎在**音频还在播放时**退出，音频服务器还引用着这个流；
   而 `--quit-after` 这条退出路径**不走正常的场景树拆解**，
   所以 `_ExitTree` 和 `NotificationPredelete` 都不会被调用。
   **这是引擎关停顺序的问题，不是游戏逻辑的缺陷。**

处理方式：加进 `tools/godot-run.ps1` 的已知噪音白名单，并把上面这段调查写进注释。

> **两条通用教训：**
> ① **Godot 对象不要放在静态字段里。** 要缓存就缓存在**节点**上。
> ② **需要"退出时释放"的资源，光挂 `_ExitTree` 不够** ——
>    非正常退出路径上它不会触发。但**先查清楚再决定**，
>    不要因为"加个 try/catch 就不报了"而掩盖真问题。
>
> 排查顺序也是通用的：**先怀疑自己 → 再怀疑引用 → 最后让工具告诉你答案，而不是继续猜。**

## 十、五条练习任务的提示

### ① 新建 Music / Sfx 两条总线，并做音量设置界面
**难度**：★★ 已经做了（总线在 `AudioManager`，界面在暂停菜单）。

练习：
1. 按 `ESC` 打开暂停菜单，拖动滑块 —— **面板上的总线音量会实时变化**。
2. **回答**：滑块应该是线性的还是对数的？
   （提示：**人耳对音量的感知接近对数**。线性滑块拖到一半听起来"还是很响"，
   所以要用 `linear_to_db`。本站的 `SetBusVolumeLinear` 内部就做了这个转换。）
3. **挑战**：加一条 `UI` 总线，让界面音效不受 `Sfx` 音量影响
   （很多玩家想单独关掉"按钮咔哒声"）。

### ② 实现 SFX 复用池：同时最多 12 个音，超出抢占最早的
**难度**：★★★ 已经做了。练习：

1. **连按 `3` 二十次**，看面板上「正在发声」卡在 12。
2. 把 `SfxVoiceCount` 改成 `4`，再连按 —— 抢占会变得非常明显（爆炸音互相打断）。
   **回答**：为什么 4 个不够？12 个够吗？这个数字该怎么定？
   （提示：看**同时**最多会有几个音。手机游戏通常只能给 8~16 个，
   PC 可以更多 —— **这是个性能预算问题，不是音质问题**。）
3. **挑战**：给音效加**优先级**，抢占时优先砍掉优先级最低的。
   然后回答：**背景环境音和打击音，谁的优先级高？**
   （提示：打击音 —— 它是**玩家操作的直接反馈**，被砍掉会让玩家以为"没打中"。）

### ③ 实现音乐交叉淡入淡出（需要两个播放器）
**难度**：★★★ 已经做了。练习：

1. 按 `4` 切换音乐，注意过渡 —— **两首曲子有 1.2 秒是重叠的**。
2. 把 `fadeSeconds` 改成 `0`，再切一次 —— 你会听到一个很硬的断点。
   **这就是"只有一个播放器"的效果。**
3. **挑战**：加"**战斗音乐**"—— 进入战斗时交叉淡入战斗曲，脱战后淡回探索曲。
   **回答**：如果战斗只持续 3 秒，而淡入要 1.2 秒，会发生什么？
   （提示：音乐会一直在淡入淡出、永远到不了满音量。
   **需要"最短播放时长"或"状态防抖"。**）

### ④ 给打击音效加 ±10% 随机音高，听是不是不腻了
**难度**：★★ 已经做了。练习：

1. 把 `variation` 改成 `0`，连按 `1` 十次 —— **非常机械**。
2. 改成 `0.10`，再连按 —— 立刻活了。
3. 改成 `0.5`（±50%），再连按 —— **过头了**，听起来像坏了。
   **回答**：上限大概在哪？（提示：一般 5%~15%。音高也影响时长，太大就变调了。）
4. **挑战**：加**音量**随机（±2 dB）叠加在音高随机之上。
   回答：**为什么"音高 + 音量"两个都随机，比只随机一个更自然？**
   （提示：真实世界的声音从来不会只在一个维度上变化。）

### ⑤ 加静音快捷键和「切到后台自动静音」
**难度**：★★ 已经做了。练习：

1. 按 `5` 静音，再按 `5` 恢复。
2. **把游戏切到后台**（Alt+Tab），音乐应该自动静音；切回来恢复。
3. **回答**：为什么 `_manualMuted` 这个标志是必要的？
   （提示：**自动行为不能覆盖玩家的显式选择。**）
4. **挑战**：加"**音量渐变**"—— 静音时不是立刻断掉，而是 0.2 秒淡出。
   **回答**：为什么硬切会让人不适？（提示：声音的突然中断在听觉上等同于"爆音"。）

## 十一、常见坑速查

| 现象 | 原因 |
|---|---|
| 音效多了爆音 / 削波 | 没有池化，几十个音同时响。**用复用池限制同时发声数** |
| 打得最热闹的时候卡一下 | 每次播放都在新建播放器节点。**池化** |
| 调音乐音量把音效也调了 | 没用总线，直接改的 Master |
| 换音乐时很突兀 | 只有一个播放器。**交叉淡入需要两个** |
| `ObjectDB instances were leaked at exit` | **Godot 对象放在了静态字段里**；或者音频还在播时引擎退出（见第八节） |
| 连播同一个音效很机械 | 没做音高 / 音量随机 |
| 静音后音量回不来 | 用了 `SetBusMuted` 又想用音量值判断状态。**静音和音量是两个维度** |
| 切后台自动静音后切回来没声音 | 只处理了 `FocusOut`。**`FocusIn` 也要处理** |
| 音效随机音高之后节奏乱了 | 音高会影响时长。**对节奏敏感的音效别随机** |
