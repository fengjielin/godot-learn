# S03 · 物理与碰撞

> **练什么**：碰撞层/掩码 · CharacterBody2D 与 RigidBody2D · Area2D · RayCast2D
> **一句话**：**层（layer）是「我是什么」，掩码（mask）是「我要检测什么」。**
> **难度**：★★★☆☆（概念只有一句话，但它是新手卡住最多、报错信息最少的地方）

---

## 一、先玩一遍

场地分成四个实验台，各完成一个目标即通关（底部状态行实时显示四个进度）。

### A 射击台 · 层与掩码
按 `1` `2` `3` `4` 切换子弹的**碰撞掩码预设**，然后按 `J` / 鼠标左键射击：

| 预设 | 掩码 | 会发生什么 |
|---|---|---|
| 1 | `Enemy` only | **子弹直接穿过墙**，命中墙后的靶子 |
| 2 | `World` only | 被墙挡下；**正对着靶子开枪也打不到它** |
| 3 | `Enemy \| World` | 先撞到谁就停在谁身上（「正常」的子弹） |
| 4 | `0`（空） | 一路飞过去，墙和靶子都当它不存在 |

**这一栏就是整站的精华。** 代码一行没变，只改了 `CollisionMask` 一个整数，
子弹的行为就从"被墙挡住"变成"穿墙而过"。左上角面板实时显示当前的
`layer` 与 `mask` 数值，对照着看。

### B 推箱子
把木箱从左边推到右边的绿边垫子上。

### C 视线台
炮塔用一条射线盯着你：**看得见是红线，被挡住变绿线**。
躲到掩体后面，累计"未被发现"满 3 秒即可。

### D 毒池
走进去会持续扣血（每 0.45 秒 −12 HP）。承受 5 次伤害即可。
右上角治疗垫可以回血；血扣光会被送回起点。

## 二、核心概念一：层与掩码

这是全站最该记住的东西。

```
collision_layer = 「我是什么」   —— 把自己登记到哪些层上
collision_mask  = 「我要检测什么」—— 我想发现哪些层上的东西
```

**两者是独立的。** 一个物体可以"属于 A 层，但只检测 B 层"（本站的子弹就是这样）。

一次碰撞要成立，需要**双向匹配**：

```
A 想发现 B  →  A.mask 必须包含 B.layer
（如果是 A 想被 B 发现 → B.mask 必须包含 A.layer）
```

本站的对照：

| 对象 | layer | mask | 含义 |
|---|---|---|---|
| 墙（StaticBody2D） | `World` | `0` | 我是墙，我什么都不主动检测 |
| 玩家（CharacterBody2D） | `Player` | `World` | 我是玩家，我只关心撞墙 |
| 子弹（Area2D） | `Projectile` | **可切换** | 我是子弹，检测谁由掩码决定 |
| 靶子（Area2D） | `Enemy` | `0` | 我是敌人，等着被打 |
| 毒池（Area2D） | `Interactable` | `Player` | 我检测玩家进没进来 |

**最容易犯的错**：只改了一边。
比如"子弹打不到敌人"，可能是因为子弹的 mask 里没有 `Enemy` 层，
**也可能**是因为敌人的 layer 不是 `Enemy`。两边都要看。

**为什么值得用它，而不是"撞到了再判断类型"**：
掩码是交给物理引擎去过滤的。不在掩码里的东西**根本不会产生碰撞事件** ——
省掉了检测开销，也省掉了每个回调里的 `if (other is Enemy)`。
**把"该不该交互"提前到引擎里解决，是碰撞系统设计的核心思路。**

数字对照（`common/physics/GameLayers.cs` 里有完整定义）：

```
层号:  1     2      3     4            5            6            7      8
值:    1     2      4     8            16           32           64     128
名称:  World Player Enemy PlayerAttack EnemyHurtbox Interactable Pickup Projectile
```

> 在场景里设的是**数字**，在代码里用的是**常量名**。两边必须一一对应 ——
> 这是 `GameLayers.cs` 存在的唯一理由。

## 三、核心概念二：monitoring 与 monitorable

`Area2D` 有两个长得很像、但作用完全不同的开关：

| 属性 | 含义 |
|---|---|
| `monitoring` | **我主动检测别人吗？**（关掉后 `BodyEntered` / `AreaEntered` 不再触发） |
| `monitorable` | **别人能检测到我吗？**（关掉后别人的 `AreaEntered` 不会报我） |

本站三种典型姿态：

| 对象 | monitoring | monitorable | 为什么 |
|---|---|---|---|
| 子弹（攻击框 hitbox） | ✅ true | ❌ false | 主动去撞别人，不需要被别人撞 |
| 靶子（受击框 hurtbox） | ❌ false | ✅ true | 只被动挨打，从不主动找别人 |
| 毒池（触发器） | ✅ true | ❌ false | 主动检测玩家有没有进来 |

**靶子设成 `monitoring = false` 有两个好处**：
少一份检测开销（场上可能有几百个受击框），
以及**从代码上表明意图** —— 读到这里的人立刻知道"这个 Area2D 是用来挨打的"。

## 四、核心概念三：CharacterBody2D 推 RigidBody2D

这是最反直觉的一点：**玩家撞上箱子时，箱子不会动。**

原因：`CharacterBody2D` 的位移是**你自己算**的（`Velocity` + `MoveAndSlide`），
它和物理引擎之间只有"碰撞求解"这一层关系 —— 引擎负责让玩家停下，**不负责传递力**。
想让箱子动，必须自己处理。

做法在 `src/entities/player/Player.cs` 的 `PushRigidBodies()` 里，逻辑是：

1. `MoveAndSlide()` 之后立刻读 `GetSlideCollision(i)`（**下一帧就被覆盖了**）；
2. 看撞到的是不是 `RigidBody2D`；
3. 往推动方向补足箱子的速度。

**关键的一处工程取舍（值得单独说）**：
最初的实现是每帧 `ApplyImpulse` —— 听起来更"物理正确"。
实际测下来它的表现很差：玩家一撞到箱子就被碰撞判定停住，得重新加速才追得上，
整个过程变成"一撞一停"，箱子的平均速度只有理论值的 **三分之一**，
而且会随帧率与阻尼变化。改箱子重量、改摩擦力都会让手感变一遍，**关卡没法设计**。

改成"直接补足速度"之后，箱子以固定速度稳定前进，完全可预测。

> **结论：关卡设计需要的是可预测，不是物理正确。**
> 真实项目里推箱子、推石块也基本都是这么做的。

另外方向取的是**主轴**（`|Δx| >= |Δy|` 就只推 X）而不是"从玩家指向箱子"的真实方向。
真实方向在从角落推时会带一个垂直分量，箱子会慢慢往侧面漂 —— 推几次就偏离目标垫了。

## 五、核心概念四：RayCast2D

射线回答的永远是一个问题：**从 A 到 B 这条直线，中间有没有挡住它的东西。**

视线、子弹轨迹、地面检测、鼠标拾取，全是这一个问题的变体。

```csharp
_ray.TargetPosition = TargetNode.GlobalPosition - GlobalPosition;
_ray.ForceRaycastUpdate();       // 立刻算，别等下一个物理帧
HasLineOfSight = !_ray.IsColliding();
```

三个容易踩的点：

1. **射线没有粗细**。它只会被**在 `CollisionMask` 里**的物体挡住。
   本站把射线的 mask 设成只含 `World` —— 于是玩家和箱子都不会挡视线，只有墙和掩体会。
   想让敌人互相挡视线，就把 `Enemy` 也加进去。
2. **`TargetPosition` 是相对于射线自己的坐标**，不是全局坐标。
3. **射线没有长度限制** —— "射程"要自己另外判（见 `SightRange`）。

还有一个小技巧：把 `Enabled` 设成 `false`、再手动 `ForceRaycastUpdate()`。
这样能保证读到的结果就是"这一帧、这个方向"的，不会和引擎的自动更新打架。

## 六、核心概念五：Area2D 的两种用法

本站**两种都用了**，可以直接对照：

| 用法 | 代码 | 特点 |
|---|---|---|
| **事件** | `_hazard.BodyEntered += ...` / `BodyExited += ...` | 只在进出**那一瞬间**触发一次 |
| **每帧查询** | `_hazard.GetOverlappingBodies().Count > 0` | 每帧问一次"现在谁在里面" |

选择标准：
- **进入/离开时要触发一件事**（播提示、开门、计分）→ 用事件；
- **在区域内要持续做一件事**（持续扣血、回复、加速）→ 用每帧查询。

毒池两个都需要：进出时给提示（事件），站在里面时持续扣血（每帧查询）。

## 八、五条练习任务的提示

### ① 只用碰撞层设置让子弹只打敌人、不打墙
**难度**：★
按 `1` 切到预设 1 就是这个效果。**但真正的练习是去编辑器里做一遍**：

打开 `bullet.tscn`，在检查器里找到 `Collision` 分组，
把 `Mask` 里的层勾选框一个一个试过来，对照运行时面板上的数字。
**你会发现勾选框和那个整数是一回事** —— 第 N 个勾 = `1 << (N-1)`。

然后做这件更有价值的事：把靶子的 `Layer` 从 `Enemy` 改掉，
回到游戏里开枪 —— 子弹再也打不中它了。
**这证明碰撞是"两边都要对"的**，只查一边永远找不出问题。

### ② 实现推箱子：把箱子推到指定位置
**难度**：★★★
已经能用了。要做的练习：

1. 把 `Player.PushSpeed` 从 180 改成 600，试试看会发生什么。
   （提示：箱子会比玩家还快，玩家一推它就跑掉了，根本推不到位置。
   **推得动 ≠ 推得准。**）
2. 把 `push_box.tscn` 的 `linear_damp` 从 6 改成 `0.1`，再推一次。
   （提示：箱子会滑很久才停，控制的精度大幅下降。）
3. **真正的挑战**：现在只能推一个轴。改成"可以斜着推"，
   然后回答：为什么斜推会让关卡设计变难？

### ③ 用 RayCast2D 做视线判定
**难度**：★★
现有实现只把 `World` 层算作遮挡。练习：

1. 把 `Turret._ray.CollisionMask` 改成包含 `Player`。
   想想为什么这样会让炮塔"永远看不到你"。
   （提示：射线起点在炮塔内部，而射线一旦碰到第一个物体就停。
   如果射线起点在某个碰撞体内部，它一出门就撞上了。）
2. 加一个"视野锥"：只有当玩家在炮塔朝向 ±60° 以内才算看见。
   提示：用 `toTarget.AngleTo(Vector2.Right)` 拿到夹角。
   （这正是 S08 敌人 AI 要做的第一步。）
3. 让掩体**可以被打掉**：子弹打中掩体后它消失，炮塔的视线立刻通了。
   你会发现子弹和视线用的是**同一套碰撞层**，只是角度不同。

### ④ 用 Area2D 做伤害区域，并提示进入/离开
**难度**：★★
现有实现两种用法都用上了。可以做的改动：

1. 加一个"减速区"：在区域内移动速度减半（每帧查询的用法）。
2. 加一个"开关区"：踩上去灯亮、离开灯灭（事件的用法）。
3. 加一个**只在毒池里生效的 Buff**：中毒状态在离开后还要持续 2 秒
   （这是 S16 状态效果的前置练习）。

### ⑤ 打开 调试 -> 可见碰撞形状，对照层设置观察
**难度**：★（但收益极高）
运行游戏后，在编辑器菜单里打开 **调试 → 可见碰撞形状**。
你会看到每个碰撞体的真实轮廓。

**然后做这件事**：把 `GameLayers` 里某一层的值改错（比如把 `Enemy` 写成 `1 << 5`，
而 `Interactable` 也是 `1 << 5`），回到游戏里看会发生什么。
**两个不相干的东西开始互相触发** —— 这就是层冲突。
真实项目里层冲突的排查极其痛苦，所以从一开始就要有一张"层分配表"并且严格遵守。

## 九、常见坑速查

| 现象 | 原因 |
|---|---|
| 碰撞完全不触发 | 掩码没包含对方的层，**或者**对方的层不是你以为的那个。两边都要查 |
| 只在编辑器的"可见碰撞形状"里看得到、运行时没反应 | `monitoring` 被关了 |
| 别人检测不到我 | `monitorable` 被关了 |
| 射线永远不撞任何东西 | `TargetPosition` 写成了全局坐标（它要的是相对坐标） |
| 射线结果比视觉慢一帧 | 用了自动更新。改 `ForceRaycastUpdate()` 手动更新 |
| 玩家能穿墙 | 玩家的 `mask` 里没有 `World` 层 |
| 两个不相干的东西互相触发 | 层值冲突（两个层用了同一个位） |
| 箱子推不动 | `CharacterBody2D` 不会自动传递力，必须自己处理 |
| 箱子推着推着跑偏了 | 施力方向带了垂直分量。改用主轴方向 |
