# S11 · 存档与读档

> **练什么**：JSON 序列化 · 多存档槽 · 自动存档时机 · 校验和 · **版本迁移**
> **一句话**：存档真正难的地方，是**「三个月前的老存档还能不能读」**。
> **难度**：★★★☆☆（写个存读十分钟，让它三年后还能读要三年功力）

---

## 一、先玩一遍

房间里散着金币，走过去就捡。把**位置、金币数、解锁内容、音量设置**存进三个独立槽位之一，再读回来 —— 玩家会被**瞬移回存档时的位置**。

| 按键 | 作用 |
|---|---|
| `1` `2` `3` | 选择槽位 |
| `4` | 保存到当前槽位 |
| `5` | 从当前槽位读取 |

**槽位 3 里预置了一份 v1 格式的旧存档**（缺少 v2 新加的字段）。读它，你会看到迁移把缺的字段补上默认值。
**第一次读取校验通过后，程序会自动把它改坏一次** —— 再按 `5` 就能看到"校验和不匹配"的警告。

## 二、核心概念一：存哪里 —— `user://` 而不是 `res://`

```
【存档目录】...\app_userdata\Godot Dojo\saves
　（`user://` 的真实路径 —— 导出后 `res://` 是只读的，玩家数据只能写这里）
```

> **游戏自带的资源用 `res://`，玩家产生的数据一律用 `user://`。**

往 `res://` 写文件**在编辑器里能跑**（因为编辑器下它就是磁盘上的一个目录），
**但导出成可执行文件之后必然失败** —— 因为 `res://` 被打进了 `.pck`，是只读的。

这类 bug 的可怕之处在于：**它不会在开发期暴露**。你在编辑器里测了一百遍都是好的，
打包发给玩家才发现存档功能完全不工作。**只有一条防线：从一开始就写对。**

面板上直接显示了 `user://` 的真实路径 —— 用记事本打开那个目录，你能看到三个 `.json` 文件。
**存档是你可以直接看、直接改的。** 这一点在调试时价值巨大。

## 三、核心概念二：为什么用 JSON 而不是二进制

| | JSON | 二进制 |
|---|---|---|
| 能用记事本打开 | ✅ | ❌ |
| 能手动改一行复现 bug | ✅ | ❌ |
| 能 diff 两个存档找差异 | ✅ | ❌ |
| 能一眼看懂迁移前后的变化 | ✅ | ❌ |
| 体积 | 大 | 小 |
| 防玩家篡改 | ❌ | 稍好 |

> **存档是你最需要调试的东西之一。** 对这个规模的游戏，**可读性远比那几 KB 重要。**

面板上把当前槽位的**原始 JSON** 直接印出来了 —— 这就是"可调试"的具体样子。

## 四、核心概念三：版本迁移（本站的重点）

```csharp
public const int CurrentVersion = 2;

public static void Migrate(SlotData data)
{
    if (data.Version >= CurrentVersion) return;

    if (data.Version < 2)
    {
        // v1 → v2：补上 LastStation
        if (string.IsNullOrEmpty(data.LastStation))
            data.LastStation = "(由 v1 旧存档迁移而来，无此字段)";
    }

    data.Version = CurrentVersion;
}
```

三条纪律：

1. **版本号从第一版就要写。** 没有它，你以后改了结构就没法判断"这文件是哪个年代的"，
   只能靠猜字段在不在 —— 那会写出一堆 `if`。
2. **只往前补，不改旧字段的含义。** 如果连老字段的意思都要变，
   那就**新加一个字段 + 在迁移里做转换**，而不是就地改原字段 ——
   否则你无法同时支持新旧两种存档。
3. **迁移必须能重复执行。** 同一个文件被迁移两次结果应该一样（幂等）。

### ★ 本站踩到的一个坑

面板原本用 `Read()` 返回的 `Version` 判断"这是不是旧存档"，但 **`Read()` 内部已经迁移过了**，
所以版本永远是当前的 —— "这是 v1 旧存档"这个信息**在读取的那一刻就被抹掉了**。

修法是加一个 `PeekVersion()`：**在迁移之前先看一眼文件里写的版本号。**

> **「文件里是什么」和「内存里是什么」是两件事。想知道前者，就必须在迁移之前看。**

## 五、核心概念四：校验和（任务 ③）

```csharp
public static string ComputeChecksum(SlotData d)
    => $"{d.Version}|{d.PlayerX:0.###}|{d.PlayerY:0.###}|{d.Coins}|{d.Unlocked.Count}|{d.MasterVolume:0.###}";

// 写入时：**必须在写完所有字段之后**算
data.Checksum = SlotData.ComputeChecksum(data);
```

它**不是防作弊，是防"看不懂的崩溃"**：
文件被截断、玩家手改错了一个标点、磁盘写了一半断电 ——
这些情况 JSON 反序列化可能"成功"但内容已经不对了。

有了校验和，你能明确区分：

- **存档坏了** → 退回默认值、提示玩家
- **存档是好的但数据奇怪** → 去查游戏逻辑

> 注意：**这不能防篡改**（玩家改完重算校验和即可）。
> **校验和解决的是"意外损坏"，不是"恶意篡改"。** 别把它当反作弊手段。

本站在校验失败时的策略是**"坏了也让你读，但明确告诉你坏了"**。
换成"坏了就拒绝读取"同样合理 —— 取决于你想让玩家损失多少。

## 六、核心概念五：自动存档的时机（任务 ②）

```csharp
private void AutoSave(string reason) { ... }

// 绑在"值得记住的时刻"上：
AutoSave("进入本站（每次进入练习站存一次）");
AutoSave("捡到金币");
```

> **自动存档要绑在「值得记住的时刻」上，不是绑在计时器上。**

反面做法是"每 N 秒无脑存一次" —— 它会在玩家**正要死的时候把濒死状态存下来**。

好时机的特征：
- **进入关卡时** —— 保证"至少有一个存档点"
- **获得重要物品时** —— 保证玩家不会因为崩溃丢掉成果
- **完成一段挑战后** —— 保证进度不倒退

本站保留了一个 12 秒的兜底计时器，**只是为了让你在演示里不用等太久** —— 这不是推荐做法。

## 七、代码地图

| 文件 | 负责什么 |
|---|---|
| `src/stations/s11_save/SaveSlots.cs` | ★ `SlotData`（数据结构 + 迁移 + 校验和）、`SaveSlots`（三槽位读写） |
| `src/stations/s11_save/S11Save.cs` | 站台：金币 / 面板 / 原始 JSON 展示 |
| `common/save/SaveSystem.cs` | 全游戏的**单**存档（练习进度），与本站的多槽位是两套东西 |

**为什么要两套？** `SaveSystem` 存的是"练功房自己的进度"（哪些站通过了），
S11 演示的是"游戏存档"（多槽位、玩家数据）。**把它们分开是有意的**：
练习站的实验**不应该污染你的练功房进度**。

## 八、五条练习任务的提示

### ① 加一个字段，然后故意读旧存档，写迁移逻辑让它不崩
**难度**：★★★ 已经做了。练习：

1. 给 `SlotData` 加一个 `PlayTimeSeconds` 字段，把 `CurrentVersion` 改成 `3`，
   在 `Migrate` 里加 `if (data.Version < 3) data.PlayTimeSeconds = 0f;`。
   **然后去读槽位 3 的 v1 文件** —— 它会一次跑完 v1→v2→v3 两段迁移。
2. **把迁移逻辑删掉再读一次** —— 你会看到字段是默认值 `0`，**程序并没有崩**。
   这说明：C# 的默认值**恰好**在这种情况下救了你。
   但如果新字段是引用类型（比如 `List<string>`），默认值就是 `null` → **NullReferenceException**。
   **所以迁移不是可选的，只是在简单情况下会被默认值掩盖。**
3. **挑战**：故意**删掉**一个字段（而不是加），写迁移让它能读。
   （提示：老存档里有、新代码不需要了 —— 这时你**什么都不用做**，
   多余字段会被忽略。**加字段要迁移，删字段不用。**）

### ② 做 3 个存档槽 + 每 30 秒自动存档
**难度**：★★ 已经做了（三槽位 + 两个自动存档时机 + 12 秒兜底）。
练习：

1. 把兜底计时器从 12 秒改成 30 秒，然后**回答**：
   **这个"每 30 秒"到底解决了什么问题？** 如果答不上来，就说明它不该存在。
2. 加一个"**存档缩略图**"（记录玩家位置 + 一张小截图）。
   （提示：截图用 `Viewport.GetTexture().GetImage().SavePng()` 存到 `user://`，
   存档里只存文件名。**大块数据不要塞进 JSON。**）
3. 加"**继续游戏**"功能：读最近一次保存的槽位，并跳转到记录的场景。
   （本站存了 `LastStation` —— 这正是它的用途。）

### ③ 写入前做一次校验（校验和或版本号）
**难度**：★★ 已经做了。练习：

1. 本站的校验和是**拼字符串**，很朴素。换成正经的哈希
   （`System.Security.Cryptography.SHA256`）再测一次。
   **回答**：对一个单机游戏，值得吗？（提示：考虑一下"玩家想改存档"这件事。）
2. 改成"**写入时先写临时文件，成功后再改名覆盖**"。
   **这一步解决的是真问题**：如果游戏在写存档的中途崩溃/断电，
   原存档就已经被破坏了一半。**先写临时文件再原子替换，能保证"要么是旧档，要么是新档"。**
3. **挑战**：给存档做一次**备份轮转**（`slot1.json` → `slot1.bak1.json` → `slot1.bak2.json`）。
   什么时候用得上？（提示：玩家的存档被某个 bug 写坏了，而他自己不知道。）

### ④ 把游戏设置（音量、全屏）也存进去
**难度**：★★ 已经做了（`MasterVolume`）。

但这里有个**值得想清楚的设计问题**：

> **游戏设置应该存在"存档"里，还是存在"独立的配置文件"里？**

- 存在**存档**里：换存档 = 换设置。"我的存档是耳机音量，另一个存档是音箱音量" —— 通常没人想要这个。
- 存在**独立配置**里：换存档不影响设置 —— **这是绝大多数游戏的做法。**

所以本站**同时存在两套**：`common/save/SaveSystem.cs` 和 `common/settings/GameSettings.cs`
共用一份 JSON，而练习站自己的槽位里**故意也存了一份音量** ——
**为的是让你看见这个错误示范长什么样。**

练习：把 `MasterVolume` 从 `SlotData` 里删掉，改成读 `GameSettings`。
**然后回答：为什么"设置"和"进度"应该分开存？**

### ⑤ 找到 user:// 的真实路径，用记事本打开看看
**难度**：★
面板第一行就是真实路径。练习：

1. 打开那个目录，**用记事本改一个数字**（比如把 `Coins` 从 3 改成 999），保存，回游戏按 `5`。
   你会看到 **"校验和不匹配"** 的警告，但**数据还是被用上了**（金币变成 999）。
   **回答**：你希望游戏在这种情况下怎么做？
2. **删掉整个 `saves` 目录**，回游戏按 `5` —— 程序应该优雅地说"槽位是空的"，而不是崩。
   （本站的 `Read()` 返回 `null`，站台会提示。**永远假设文件不存在或已损坏。**）
3. 把 `slot3.json` 的 `Version` 改成 `1` 但不删其他字段，按 `5` ——
   你会看到迁移逻辑**照样跑了一遍**。
   **回答**：这说明迁移的判断依据是什么？如果玩家把 `Version` 改成 `99` 会怎样？
   （提示：`if (data.Version >= CurrentVersion) return;` ——
   一个"未来版本"的存档会被当成当前版本，可能出问题。
   **健壮的实现应该处理"版本比我新"的情况**，通常是明确拒绝并提示"请升级游戏"。）

## 九、常见坑速查

| 现象 | 原因 |
|---|---|
| 编辑器里好好的，导出后存不了档 | 写了 `res://`。**玩家数据只能写 `user://`** |
| 加字段后老存档读出来是 `null` 然后崩 | 没写迁移，而且新字段是引用类型（默认 `null`） |
| 迁移逻辑跑了两次，结果不对 | 迁移不幂等。**同一个文件迁移两次结果必须一样** |
| 分不清"这是旧存档"和"这是迁移后的存档" | 在迁移之后才检查版本号。**要先 `PeekVersion`** |
| 存档写一半崩溃，文件全毁了 | 没有"先写临时文件再原子替换" |
| 玩家改了存档，游戏行为诡异但没报错 | 没有校验和，或者校验失败了但照用不误 |
| 自动存档把濒死状态存下来了 | 存档时机绑在计时器上，而不是"值得记住的时刻"上 |
| 换存档把音量设置也换了 | 设置和进度存在一起了。**它们应该分开** |
| `The InputMap action "aux_6" doesn't exist` | **加了新按键但 InputMap 里没有这个动作**（本工程踩过）。用 `tools/gen-inputmap.ps1` 统一生成 |

## 十、通关后做什么

1. **把 `SlotData.CurrentVersion` 改成 `99`**，然后按 `5` 读槽位 3。
   `if (data.Version >= CurrentVersion) return;` 会直接跳过迁移 ——
   你会得到一个 v1 数据被当成 v99 使用的状态。**这就是"未来存档"的问题。**
   加上拒绝逻辑，然后回答：**游戏降级到旧版本时，新存档该怎么办？**
2. 打开 `common/save/SaveSystem.cs`，看它的 `Load()` 里的 `catch` 分支：
   它**不抛异常，而是退回全新存档 + 备份坏文件**。
   **这是存档代码最重要的一个设计决定** ——
   **存档功能崩溃，绝不能让游戏起不来。** 你宁愿玩家丢一点进度，也不愿他打不开游戏。
3. 想清楚：本站的 `SaveSlots` 是**站内**的，而 `SaveSystem` 是 Autoload 的。
   **为什么练习站的多槽位实现没有提升成公共模块？**
   （提示：只有一个地方用它。**等第二个使用者出现再提取，不要提前抽象。**）
