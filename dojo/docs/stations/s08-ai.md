# S08 · 敌人 AI 与寻路

> **练什么**：视野锥 · 听觉 · 导航网格 · 群体分离 · 丢失目标后的搜索
> **一句话**：敌人的"聪明" = **它知道多少信息** + **它怎么走到你面前** + **它和同伴怎么相处**。
> **难度**：★★★★☆（每一项都简单，难的是它们要**同时**工作还不打架）

---

## 一、先玩一遍

五只敌人在迷宫里巡逻。你走进去，它们会：

| 能力 | 表现 | 按键关掉之后 |
|---|---|---|
| **视野锥** | 朝向 ±60°、300 像素内、且视线没被墙挡住才看得见你 | 变成 360° 全向视野，绕背后没用 |
| **听觉** | 按住 `Shift` 冲刺会持续发出噪音，420 像素内的敌人会去查看 | 冲刺不再吸引任何敌人 |
| **寻路** | 沿导航网格绕开墙追你 | 直线朝你走，一头撞在墙上 |
| **分离力** | 五只摊开成包围圈 | 五只叠成一坨，看起来像一只 |
| **搜索** | 丢失目标后去最后知道的位置找 3 秒 | 立刻忘记，直接回巡逻 |

左上角面板按 `1`~`5` 逐个切换它们。**关掉一条再玩一遍，你就知道那一条值多少。**

## 二、核心概念一：导航网格到底是什么

**它就是一组互相连通的凸多边形，拼出关卡里"能走的地方"。**

寻路算法在这张图上找路径。所以：

> **敌人会绕开墙，不是因为它聪明，而是因为导航网格里根本没有墙那一块。**

理解这一点之后，导航就不再是黑魔法了 —— 它只是**一份"哪里能走"的数据**。

### 编辑器烘焙 vs 代码生成

编辑器里的「烘焙」按钮做的是同一件事：读场景里的静态碰撞体 → 扣除掉它们 → 把剩下的区域切成多边形。

本工程改用**代码生成**（`common/nav/NavMeshBuilder.cs`），理由是：

- 结果在任何机器上**完全一致** —— 编辑器烘焙会随版本和设置漂移，自动化验证就没意义了；
- 程序化生成的关卡（S15）本来就无法预先烘焙，**它必须在运行时生成**。

算法很朴素：把可走区域切成 40 像素的格子，去掉与墙相交的，每个空格子输出成一个四边形。
本关的输出是 **372 个多边形**（面板上能看到）。

代价：格子越细越贴合、多边形越多。真实项目里应该用更聪明的算法（把相邻空格子合并成大矩形）。
**但先让它跑起来，再让它跑得快 —— 顺序不要反。**

### ★ 一个必须遵守的工程纪律

本关的墙只定义了**一次**（`S08Ai.WallRects`）：

```csharp
private static readonly Rect2[] WallRects = { new(760,150,44,240), ... };

// ① 看得见 —— 画出来
// ② 撞得到 —— 生成碰撞形状
// ③ 走得到 —— 用同一份数据生成导航网格
```

**如果墙的碰撞和导航网格来自两份不同的数据，你迟早会遇到
"敌人撞在看不见的墙上"或者"敌人穿墙走过来" —— 而且极难调试**，
因为两边单独看都是"对"的。

> **同一份数据 → 多个表示，而不是多个数据源。**

## 三、核心概念二：群体分离

五个敌人各自朝玩家走，如果**没有任何相互排斥**，它们的路径会完全重合 ——
最后看起来像**一个**敌人。分离力就是给每个敌人加一条"离同伴远一点"的力：

```csharp
foreach (var other in 同组敌人)
{
    var offset = GlobalPosition - other.GlobalPosition;
    var distance = offset.Length();
    if (distance > SeparationRadius) continue;
    push += offset.Normalized() * (1f - distance / SeparationRadius);  // 越近推力越大
}
direction = (寻路方向 + push * SeparationWeight).Normalized();
```

这是 Boids（鸟群）三条规则里最简单的一条。另外两条（对齐、聚拢）在敌人 AI 里通常不需要。

### 参数不是拍脑袋定的 —— 有一条算术

5 个敌人围成一圈时，相邻间距 ≈ **1.18 × 半径**。
所以想要 70 像素的间距，`SeparationRadius` 至少要 60。

**力度更要算。** 本站最初设 `SeparationWeight = 0.85`，
实测 5 个敌人追到位之后**最小间距只有 23 像素** —— 还是叠在一起。
原因是"朝玩家走"的力是单位长度（1.0），而分离力最多只有 0.85，
结果还是被玩家那个点吸成一坨。调到 **1.8** 之后才真的摊开成包围圈（实测间距 43 像素）。

> **做 AI 的时候，"力的量级关系"比"力的方向"更容易被忽略。**
> 方向对了但量级不对，效果就是"看起来没生效"。

## 四、核心概念三：感知与"知道多少"

```csharp
public bool CanSeeTarget()  // 三个条件缺一不可
{
    if (距离 > SightRange) return false;
    if (视野锥开启 && 夹角 > VisionHalfAngleDeg) return false;
    ray.TargetPosition = 到目标;
    ray.ForceRaycastUpdate();
    return !ray.IsColliding();      // 视线没被墙挡住
}
```

**想调整 AI 的难度，最有效的做法是调整"它知道多少信息"**，
而不是去改寻路算法：

| 想让它变笨 | 想让它变聪明 |
|---|---|
| 缩短视野 | 加长视野 |
| 缩小视野锥 | 扩大视野锥 |
| 去掉听觉 | 加听觉 + 记住声音位置 |
| 丢失目标立刻忘记 | 去最后已知位置搜索 |

**"丢失目标后搜索"这个行为，是性价比最高的一条** ——
它不增加任何算法复杂度，但会让 AI 从"要么瞎逛、要么死追"变成"像个活物"。

## 六、五条练习任务的提示

### ① 加视野锥：朝向 ±60° 且在 300 像素内才看得到你
**难度**：★★ 已经做了。练习：

1. 把 `VisionHalfAngleDeg` 改成 `180`（全向视野），再玩一次 ——
   **"绕到背后"这个策略立刻失效**。AI 的难度很多时候只是"它看得到多宽"。
2. 把 `SightRange` 从 300 改成 600，感受"狙击手敌人"是什么体验。
3. **真正的练习**：加"近距离盲区"（比如 60 像素内即使背后也能感觉到你）。
   想想为什么很多潜行游戏要这么做。（提示：**否则玩家可以贴着敌人的背走完全程**，
   这会让潜行从"读节奏"退化成"找死角"。）

### ② 加听觉：冲刺时产生的噪音会吸引附近敌人
**难度**：★★ 已经做了。练习：

1. 关掉听觉，用冲刺跑完全程 —— 你会发现难度断崖式下降。
   **这就是"速度换隐蔽"这个取舍的价值：收益必须要有代价。**
2. 现在的噪音是"瞬时事件"。改成**持续衰减的噪音源**：
   冲刺时每隔 0.45 秒留下一个会衰减的标记，敌人听到最新鲜的那个。
3. 想一想：为什么判定"听觉起效了"要盯着 `Patrol → Search` 这条转移，
   而不是盯着"玩家按了冲刺键"？
   （提示：**判定要盯着结果，不要盯着输入。** 玩家按了键但附近没人 = 没起效。）

### ③ 用 NavigationRegion2D 烘焙导航网格，让敌人绕开墙
**难度**：★★★ 已经做了（代码生成版）。练习：

1. 按 `3` 关掉寻路，看敌人一头撞在墙上 —— **这就是"没有导航"的样子**。
2. 把 `NavMeshBuilder` 的格子从 40 改成 120，看敌人会不会开始卡墙。
   （提示：格子太粗，窄通道会被整块判定成"不可走"。）
3. **挑战**：改用 Godot 的运行时烘焙
   （`NavigationRegion2D.BakeNavigationPolygon(false)`），
   并把 `NavigationPolygon.ParsedGeometryType` 设成 `StaticColliders`。
   然后在编辑器里点一次「烘焙」，对比两次得到的多边形数是否一致。
   **理解"烘焙按钮到底做了什么"，比会用那个按钮重要得多。**

### ④ 加分离力：5 个敌人一起追时不要叠在一起
**难度**：★★ 已经做了。练习：

1. 把 `SeparationWeight` 改回 `0.85`，看它们叠成一坨 ——
   **这是本站最有价值的一次"亲手制造 bug"**。
2. 把 `SeparationRadius` 改成 `200`，看它们互相躲到什么程度
   （提示：会开始"绕圈"，谁也走不到玩家身边）。
3. 加一条**对齐**规则（朝同伴的平均朝向偏一点），
   看五个敌人会不会开始像狼群一样行动 —— 然后回答：
   **这对"包围玩家"这个目标是帮助还是破坏？**

### ⑤ 加「丢失目标后搜索最后已知位置」的行为
**难度**：★★★ 已经做了。练习：

1. 按 `5` 关掉搜索，然后躲到柱子后面 —— 敌人会立刻忘记你，直接回巡逻。
   **对比一下：开着的时候，它会去你消失的地方转 3 秒。**
2. 把搜索做得更"聪明"：让它在搜索点附近**沿螺旋线扩大范围**，
   而不是站在原地。回答：这样会让游戏更难还是更容易？为什么？
3. **挑战**：加"呼叫支援" —— 一个敌人发现你时，把位置广播给 500 像素内的同伴。
   （提示：这需要一个"事件广播"的机制，S13 事件总线会正面讲这件事。
   先自己用最简单的写法实现一遍，看看代码会乱成什么样。）
4. 想一想：本关的 `Search` 状态同时承担了"去噪音点查看"和"去最后已知位置找"两件事。
   **为什么不需要拆成两个状态？** 什么情况下就必须拆了？

## 七、常见坑速查

| 现象 | 原因 |
|---|---|
| 敌人一动不动 | 导航网格是空的（烘焙失败），或者 `NavigationAgent2D` 的路径还没同步（要等一两个物理帧） |
| 敌人卡在墙角抖 | 格子太粗导致窄通道被堵死；或者 `TargetDesiredDistance` 设得太小 |
| 敌人撞在"看不见的墙"上 | 碰撞体和导航网格来自两份不同的数据。**必须同源** |
| 敌人穿墙走过来 | 同上，反过来 |
| 五个敌人叠成一坨 | 分离力没开、半径太小、**或者力度不够被"朝目标走"的力压过去** |
| 敌人互相躲来躲去走不到你身边 | 分离力过强。它和寻路方向应该是"叠加"，不是"替换" |
| AI 偶尔慢一拍 | 感知和状态机决策的执行顺序不确定。用 `ProcessPriority` 固定顺序 |
| 关掉视野锥后敌人反而更容易发现你 | 那是预期的 —— 关掉锥形就是 360° 全向视野 |

## 八、通关后做什么

1. **把五个开关全关掉，再玩一遍。** 你会发现这一站变成了"五个方块直线撞墙"。
   那个落差，就是这一整套 AI 能力的价值。
2. 打开 `F3` 性能面板，看导航的开销：
   5 个敌人时帧时间几乎没变，但把它改成 50 个敌人呢？
   （提示：`NavigationAgent2D` 每个都在做路径查询。**导航不是免费的**，
   真实项目里要给远处的敌人降频更新 —— 这个思路在 S14 会用到。）
3. 想清楚一个问题：本站的状态机和 S04 用的是**同一套代码**。
   那为什么 S04 的守卫不需要导航，而 S08 的敌人需要？
   （提示：**能力是按需加装的**。S04 在一个空场里，直线走就够了；
   S08 有墙，就必须有导航网格。**不要因为"以后可能要用"就先把东西加上。**）
4. 去 `docs/00-学习路线图.md` 看一眼自检清单里 S08 那两条，确认你能答上来。
