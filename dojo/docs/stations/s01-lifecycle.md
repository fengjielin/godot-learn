## 二、核心概念一：生命周期顺序

这是本站最重要的东西。Godot 节点的"一生"有这么几个回调：

| 回调 | 什么时候执行 | 这里能做什么 / 不能做什么 |
|---|---|---|
| `_EnterTree()` | 节点被加入场景树的那一瞬间 | 能拿到 `GetTree()`。**不能保证子节点齐全**，所以别在这里 `GetNode` |
| `_Ready()` | 节点及其**所有子节点**都进入树之后 | 最常用的初始化点。`GetNode` / `GetParent` 在这里都安全 |
| `_Process(delta)` | 每个渲染帧 | 做与画面有关的事：UI、输入读取、插值 |
| `_PhysicsProcess(delta)` | 每个物理帧（默认 60Hz 固定步长） | 做位移、速度、碰撞判定 |
| `_ExitTree()` | 离开场景树时 | 退订信号、保存状态。**对象还没真正释放** |
| （真正释放） | `QueueFree()` 排队之后、本帧末尾 | 内存在这里回收 |

**为什么 `_Process` 和 `_PhysicsProcess` 要分开？**
物理引擎以固定步长推进（默认每秒 60 次）。如果你在 `_Process` 里乘 `delta` 改速度，
那么帧率 144 的机器一秒钟会算 144 次，物理结果就与 60 帧的机器不一致 ——
表现为"**帧率越高跑得越远**"。位移一律写进 `_PhysicsProcess`。

**本站可以亲眼验证的地方**：打开 `Wanderer.cs`，`_EnterTree` / `_Ready` / `_ExitTree`
里各有一句 `GD.Print`。按住空格生成十几个方块，对照输出面板看打印顺序。

## 三、核心概念二：信号（Signal）

方块撞墙这件事，**站台想知道**（好给你显示弹跳次数），但方块不该认识站台。

```csharp
// Wanderer.cs —— 发送方：我只负责"喊一声"，不关心谁在听
[Signal] public delegate void BouncedEventHandler(int bounceCount);
...
EmitSignal(SignalName.Bounced, BounceCount);

// S01Lifecycle.cs —— 接收方：我订阅我关心的
wanderer.Bounced += OnWandererBounced;
```

C# 里自定义信号的三条规矩：
1. 用 `[Signal]` 标注一个 `delegate`；
2. delegate 名字必须以 `EventHandler` 结尾（Godot 用它推出信号名）；
3. 参数类型必须是 Variant 能表达的类型（`int` / `float` / `string` / `bool` / `Vector2` …）。

**和直接引用的区别**：直接引用是"我知道你、我调你的方法"，两者绑死；
信号是"我喊一声，谁爱听谁听"，发送方完全不需要知道接收方的存在。

**一个很容易踩的坑**：连接了信号就必须考虑什么时候断开。
- 如果**发送方**先被销毁 → Godot 会自动清理这条连接，不用管（本站就是这种情况，方块是被销毁的一方）。
- 如果**接收方**先被销毁而发送方还活着 → 连接会留在发送方身上，指向一个已释放的对象，
  之后一触发就报 `Object has been freed`。**这种必须在接收方的 `_ExitTree` 里手动 `-=`。**
  （`Hub.cs` 里订阅 `EventBus.StationCompleted` 就是这个情况，可以去看看它怎么写 `_ExitTree`。）

## 四、核心概念三：分组（Group）

```csharp
AddToGroup("wanderers");                                    // 入组
GetTree().GetNodesInGroup("wanderers").Count                // 数一数有几个
GetTree().CallGroup("wanderers", "RetreatTo", GatherPoint); // 给全组下同一条指令
```

按 `G` 触发的就是最后这行。注意 `RetreatTo` 是 `Wanderer` 上的一个普通公开方法，
`CallGroup` 通过**方法名字符串**调用它。好处是不需要持有任何方块的引用；
代价是**编译器帮不了你**（方法名写错要运行时才发现）。

分组最适合的场景：广播式操作（全体暂停、全体变色、全体存档）。

### ② 把 `Wanderer` 的存活时间从 3 秒改成 8 秒
**难度**：★
两种改法，都要会：

- **在编辑器里改**：打开 `wanderer.tscn`，选中根节点，在检查器里把 `Lifetime` 从 3 改成 8。
  这改的是**这个场景**的默认值。
- **在代码里改**：`S01Lifecycle.SpawnWanderer()` 里，`AddChild` 之前写 `wanderer.Lifetime = 8f;`。
  这改的是**这一次生成出来的实例**。

**要观察的现象**：改成 8 秒后，同样按住空格 2 秒，峰值会明显变高
（因为方块死得慢），而且 `_ExitTree` 的打印会推迟。

> `[Export]` 让字段出现在检查器里 —— 这就是"策划能在不改代码的情况下调参数"的最小形态。
> 更系统的做法见练习站 S09（数据驱动）。

### ③ 给 `Wanderer` 加一个 `OnBounced` 信号，撞墙时通知本站
**难度**：★★

### ④ 用 `GetTree().CallGroup` 给所有方块下指令
**难度**：★★
`G` 键的功能**已经实现**（`CommandAllToGatherPoint`）。这一条的任务是**换个用法**：

## 七、常见坑速查

| 现象 | 原因 |
|---|---|
| `GetNode` 返回 null | 路径写错，或它在 `_EnterTree` 里被调用（子节点还没就绪） |
| 报 `Object has been freed` | 接收方已销毁但没退订信号 |
| `CallGroup` 没反应 | 方法名拼错、或对象没进组。**方法名是字符串，编译器查不出来** |
| 方块卡在墙里抖动 | 生成位置和墙重叠了，`MoveAndSlide` 每帧都在推开 |
| 改 `Lifetime` 没生效 | 改的是 `.tscn` 的默认值，但代码里 `AddChild` 前又覆盖了一次 |
