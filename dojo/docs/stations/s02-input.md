# S02 · 输入与手感

> **练什么**：InputMap / 轮询 vs 事件 / 输入缓冲 / 土狼时间 / 可变跳跃高度 / 冲刺
> **一句话**：手感不是"调参数调出来的"，是**给玩家的失误留出的容错窗口**。
> **难度**：★★★☆☆（概念不难，但"差一点点"的差别只有亲手关掉才感觉得到）

---

## 一、先玩一遍

进入 S02 之后：

1. `WASD` 或 `←→` 左右移动，`空格` 跳跃，`Shift` 冲刺。
2. 从最左边的平台一路跳到最右边的**绿色目标环**即通关。
3. 路上有三个缺口，标注分别是 `100px / 100px / 190px`。
   **最后那个 190px 的缺口，不冲刺绝对过不去。**
4. 掉下去会自动重生在起点（左下角状态行会记下你掉了几次）。

**这一站的精华在这里**：左上角有三行开关，按 `1` `2` `3` 可以分别关掉

| 按键 | 关掉的东西 |
|---|---|
| `1` | 土狼时间（走出边缘后还能补跳的 0.1 秒） |
| `2` | 跳跃缓冲（落地前 0.12 秒内按下的跳跃会被记住） |
| `3` | 可变跳跃高度（松手就截断上升） |

**关掉它们再走一遍。** 你会立刻感觉到"这游戏怎么突然变难玩了"——
那个"变难"的量，就是这三行代码的价值。

左上角两条进度条实时显示两个计时器还剩多少，是这两个机制的可视化。

## 二、核心概念一：三种手感辅助

### ① 土狼时间（Coyote Time）

```csharp
// 站在地上时计时器一直是满的；一旦离地就开始倒数
CoyoteTimer = IsOnFloor() ? CoyoteTime : Mathf.Max(0f, CoyoteTimer - dt);
// 能不能跳：不是"在地面上"，而是"土狼计时器还没走完"
private bool CanJump() => CoyoteEnabled ? CoyoteTimer > 0f : IsOnFloor();
```

**解决的问题**：玩家跑到平台边缘，起跳晚了一两帧，结果掉下去。
玩家会觉得"我明明按了跳！"——这不是玩家菜，是设计欠账。
名字来自《跑跑卡丁车》式的动画梗：威利狼跑出悬崖后还能在空中悬停一下。

**关键点**：判断依据从"在地面上"变成"计时器 > 0"，这两个条件的区别就是那 0.1 秒的宽容。

### ② 跳跃缓冲（Jump Buffer）

```csharp
// 按下时：先不管能不能跳，记下来
private void RequestJump()
{
    if (!CanJump()) _jumpRequestedWhileUnable = true;
    JumpBufferTimer = JumpBufferTime;
}

// 每帧：只要能跳了，就把记下的那一次兑现
private void ConsumeBufferedJump()
{
    if (JumpBufferTimer <= 0f || !CanJump()) return;
    DoJump();
    JumpBufferTimer = 0f;
}
```

**解决的问题**：玩家在快落地时连按跳跃，想"落地瞬间立刻再跳"。
如果没有缓冲，那一按发生在空中 → 被丢弃 → 玩家感觉"按键没反应"。

**和土狼时间的方向刚好相反**：
土狼时间是"**离开地面之后**还认"，缓冲是"**还没落地之前**就认"。
一个往后宽容，一个往前宽容，合起来把起跳的容错窗口从 0 毫秒扩到了 220 毫秒。

### ③ 可变跳跃高度（Variable Jump Height）

```csharp
if (!Input.IsActionJustReleased("jump")) return;
if (Velocity.Y >= 0f) return;                  // 已经在下降，不用管
Velocity = new Vector2(Velocity.X, Velocity.Y * JumpCutMultiplier);
```

**解决的问题**：只有一个固定跳跃高度时，"想跳矮一点"就做不到，
近距离的精确落脚会非常难受。轻点 = 小跳，按住 = 大跳。

**注意那个 `if (!IsActionJustReleased("jump"))`**：用的是「**刚刚松开**」而不是「没有按住」。
如果写成"没按住就截断"，那么按住跳跃键的每一帧都会被反复截断，跳不高。

## 三、核心概念二：轮询 vs 事件

这一站**故意同时用了两种写法**，你可以直接对照：

| | 用在哪 | 写法 |
|---|---|---|
| **轮询** | 玩家自己的移动/跳跃/冲刺 | `_PhysicsProcess` 里 `Input.IsActionJustPressed("jump")` |
| **事件** | 站台的 1/2/3 开关 | `_UnhandledInput` 里 `@event.IsActionPressed("assist_1")` |

**轮询（polling）**
- 在 `_Process` / `_PhysicsProcess` 里主动去问"这个动作现在是什么状态"。
- 优点：时序确定，一帧只读一次，物理帧里统一决策不会乱序。
- 适合：连续状态（移动）、每个物理帧都要判断的动作（跳跃、冲刺）。

**事件（event）**
- 实现 `_Input` 或 `_UnhandledInput`，等引擎把事件推给你。
- 优点：能拿到完整的 `InputEvent` —— 于是你知道这是键盘、鼠标还是手柄触发的，
  也能拿到鼠标坐标、滚轮方向、按键的 echo 标志。
- 适合：离散的一次性触发（开菜单、切开关、点技能）。
- `_UnhandledInput` 和 `_Input` 的区别：**`_UnhandledInput` 只在 UI 没吃掉这个事件时才收到**。
  所以游戏里的操作要用 `_UnhandledInput`，否则玩家在输入框里打字时角色会乱跑。

**本站的 1/2/3 键正好演示了事件的必要性**：如果用轮询，你得在物理帧里挨个判断三个动作；
用事件则一个 `switch` 就完了，而且天然不会重复触发。

## 四、核心概念三：计时器就这三步

本站所有"窗口"类机制都是同一个模式，没有任何魔法：

```csharp
JumpBufferTimer = 0.12f;                       // 1. 某个事件发生时设成满值
JumpBufferTimer -= dt;                          // 2. 每帧减 delta
if (JumpBufferTimer > 0f) { /* 窗口还开着 */ }   // 3. 用之前判 > 0
```

冲刺冷却、无敌帧、技能 CD、Buff 持续时间、连招窗口 —— **全都是这一个模式**。
练熟它，你在 S07（无敌帧）、S16（状态效果）里会直接受益。

## 六、五条练习任务的提示

注意：**这一站的勾选不看你玩没玩过，而看你有没有真的做出对应操作**
（缓冲救回一次跳跃、土狼救回一次跳跃、跳出高跳也跳出矮跳、用三次冲刺、用过 1/2/3 开关）。
设计意图是：**把"学会了"变成可观测的事件**，而不是凭感觉说"我懂了"。

### ① 实现跳跃缓冲
**难度**：★★
代码已经有了。真正的练习是：

1. 把 `JumpBufferTime` 改成 `0f`，再玩一次。感受"落地前按跳没反应"的烦躁。
2. 改成 `0.5f`，再玩一次。感受"我明明没想跳，它自己跳了"的失控。
3. 找到那个刚好舒服的值（提示：人的反应时间约 0.15~0.25 秒，但玩家会提前预判，所以 0.1 左右通常最好）。

> **这就是"调数值"的正确姿势：先跑到两个极端，感受两端各坏在哪，再往中间收。**

### ② 实现土狼时间
**难度**：★★
同上。另外注意 `CoyoteTimer = IsOnFloor() ? CoyoteTime : ...` 这一行：
它让计时器在地面上**一直保持满值**。如果写成"离地时才设为满值"，就得处理"什么时候算离地"，
反而更容易出错。**能用状态持续重置的，就不要用状态变化来触发。**

### ③ 实现可变跳跃高度
**难度**：★★★
现有实现有个可以挑刺的地方：它只处理了"提前松手"，
**没有处理"跳到一半撞到天花板"**。想想看，如果关卡里有低矮的通道：

- 撞到天花板时 `Velocity.Y` 是负的，你会希望它被清零还是反弹？
- 如果玩家按着跳跃键撞到天花板，然后一直按着，落下来时会不会被反复触发一次"跳跃"？
  （提示：`IsActionJustPressed` 不会，但如果你写的是 `IsActionPressed` 就会。）

### ④ 加冲刺：Shift + 方向，0.5 秒冷却，冲刺过程中无敌
**难度**：★★★
冷却和方向选择都已经实现。**"冲刺过程中无敌"还没做** —— 那是 S07 的内容。
现在可以做的：

- 加一个 `DashCharges` 字段，允许存 2 次冲刺。想清楚回复时机是"每 0.5 秒回一次"还是"落地才回"。
- 加"冲刺结束时的速度衰减"：直接归零会很突兀，试试把速度降到 `MaxSpeed` 而不是 0。
- 试试允许**空中冲刺垂直方向**（八向冲刺），再判断一下关卡还设计不设计得动。

### ⑤ 分别用轮询和事件各实现一个功能
**难度**：★★
站台已经帮你各写了一个。真正的练习是**把 S01 的按键改成另一种写法**，然后回答：

- S01 的"按住空格连续生成方块"，如果改成事件写法会怎样？
  （提示：`_UnhandledInput` 只在**按下/松开那一刻**触发一次，按住不会持续触发。
  你要么自己在事件里记一个 `isHeld` 标志，要么干脆保留轮询。）
- 反过来，S02 的 1/2/3 开关如果改成轮询会怎样？
  （提示：`IsActionJustPressed` 在 `_PhysicsProcess` 里也能用，但如果你把逻辑写在
  `_Process` 里，帧率不同会导致一次按键被多个物理帧看到。）

## 七、关卡为什么是 100 / 100 / 190

这不是随便填的数字，是按角色的物理参数反推出来的：

```
起跳速度 565 px/s，重力 1750 px/s²
  满跳高度 = 565² / (2 × 1750) ≈ 91 px
  上升到顶点耗时 = 565 / 1750 ≈ 0.32 s
  水平速度 270 px/s
  → 在空中"高于起跳点 40px"的窗口是 0.081s ~ 0.565s，共 0.484s
  → 该窗口内能水平移动 0.484 × 270 ≈ 130 px
```

所以：

| 缺口 | 设计意图 |
|---|---|
| **100px** | 小于 130px 的窗口 → **不冲刺，按住跳跃就能过**。给玩家建立信心 |
| **190px** | 大于 130px，**光跳绝对过不去**；但冲刺能额外给出 `(760-270) × 0.16 ≈ 78px`，总共 ~208px → **必须冲刺** |

**这是关卡设计的基本功：先用角色的物理参数算出"能力半径"，再用关卡去卡这个半径。**
凭感觉摆平台，做出来的关卡不是太难就是太松，而且你自己说不清为什么。

（顺带一提：作者就是用这组参数算出过一次通关路线的，见下方"通关后做什么"。）

## 八、常见坑速查

| 现象 | 原因 |
|---|---|
| 帧率越高跳得越远/越快 | 位移写在了 `_Process` 里。必须在 `_PhysicsProcess` |
| 跳跃只有一种高度，松手没反应 | 用了 `IsActionPressed` 而不是 `IsActionJustReleased` 判松手 |
| 按住跳跃键人物反复起跳 | 用了 `IsActionPressed` 而不是 `IsActionJustPressed` |
| 在输入框打字时角色乱跑 | 用了 `_Input` 而不是 `_UnhandledInput` |
| 斜向移动比单向快 | 没归一化。用 `Input.GetVector` 会自动处理 |
| 手柄摇杆漂移导致角色自己走 | 没设死区。`Input.GetVector` 的最后一个参数就是它 |
| 冲刺之后立刻又能冲 | 冷却计时器忘了减 `delta`，或者判断写成了 `>= 0` |

## 九、通关后做什么

1. **关掉全部三个辅助**（按 `1` `2` `3`），再通关一次。这是本站的"真·通关"。
2. 改 `Gravity` 和 `JumpVelocity`，看关卡是变简单还是变难 —— 验证你对上面那张表的理解。
3. 把 `MaxSpeed` 调成 500，你会发现 190px 的缺口不用冲刺也能过了。
   **想一想：这说明关卡难度是由"角色能力"和"地形尺寸"共同决定的。改角色等于改关卡。**
4. 想清楚一个问题：为什么冲刺要"锁死方向"？
   （提示：如果冲刺中途可以转向，玩家能用它做出无限滞空或者原地加速，
   关卡就没法用固定距离来设计了。**给玩家自由度 = 放弃对关卡的精确控制**，
   这个取舍在后面的站里会反复出现。）
5. 去看 `docs/01-如何使用练功房.md` 里"自动化验证"那一节 ——
   作者就是用那套输入回放，把上面算出的路线跑了一遍，证明这一站真的能通关。
   **你也可以用它来验证自己改完的关卡还能不能过。**
